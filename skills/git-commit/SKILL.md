# Git Commit Skill

以下の手順でコミットを作成し、リモートへ push する。

## 手順

1. `git status`、`git diff --cached`、`git log --oneline -5` を並列実行して現在の状態を把握する。

2. ステージ済みの変更がなければ「コミットする変更がありません」と伝えて終了する。

3. 差分とログのスタイルを参考に、コミットメッセージを考える。
   - このリポジトリのコミットは**日本語**で書かれている場合、日本語で書く。
   - 1行目は変更の要旨（50文字以内が望ましい）。
   - 「何をしたか」より「なぜしたか・何が変わるか」を優先する。
   - `.env` や認証情報ファイルが含まれていたら警告してコミットを中止する。

4. ユーザーからメッセージが指定されていればそれを使い、なければ生成したメッセージを使う。

5. 以下の形式でコミットを実行する。

   ```
   git commit -m "$(cat <<'EOF'
   <コミットメッセージ>

   Co-Authored-By: Claude Sonnet 4.6 <noreply@anthropic.com>
   EOF
   )"
   ```

6. コミット後に `git status` を実行して成功を確認する。

7. pre-commit フックが失敗した場合は `--no-verify` を使わず、原因を調べて修正してから新たにコミットする。

8. 現在のブランチを `git push` でリモートに反映する。追跡ブランチが未設定の場合は `git push -u origin <branch>` を使う。

9. push 後に `git status` を実行し、リモートと同期していることを確認する。

## Rules

* ステージされていない変更を無断でステージしない（明示的に指示された場合を除く）。
* 秘密情報を含むファイル（`.env`、認証情報ファイル等）が含まれる場合は警告し、コミットを中止する。
* `--amend` や `--no-verify` は明示的な指示がない限り使わない。
* `git push --force` / `--force-with-lease` は明示的な指示がない限り使わない。

## Completion Criteria

* ステージ済みの変更がコミットされている
* コミットがリモートへ push されている
* push 後の `git status` で working tree がクリーン（または意図した状態）になっている
